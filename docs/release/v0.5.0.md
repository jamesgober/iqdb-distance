# iqdb-distance v0.5.0 — Equivalence Fuzzing + API Freeze

**The contract is fuzzed, and the surface is locked.** v0.5.0 turns the SIMD-vs-scalar equivalence guarantee from a fixed-corpus test into a fuzzed one, and freezes the public API for the 1.x series. The math layer the index crates build on is now both proven and stable.

## What is iqdb-distance?

The innermost loop of the iQDB vector database: five metrics behind one `Distance` trait, a runtime dispatcher over the `DistanceMetric` tag, a `cosine_normalized` fast path, allocation-free batch evaluation, and runtime-dispatched AVX2 / NEON kernels with a readable scalar fallback.

## What's new in 0.5.0

### Equivalence fuzzing

A standalone `fuzz/` cargo-fuzz crate (nightly) adds two targets:

- **`equivalence`** — asserts the dispatched kernel (`compute`, which routes to AVX2 / NEON on a SIMD host) agrees with the scalar reference (`compute_scalar`) within floating-point tolerance, across all five metrics. It is the fuzzed counterpart to the fixed-corpus `tests/differential.rs`: the corpus pins known-hard cases, the fuzzer explores the structural space (dimensions, SIMD-tail boundaries, sign and magnitude patterns) the corpus cannot enumerate.
- **`robustness`** — asserts `compute` returns a typed `Result` and never panics on arbitrary input, including non-finite and length-mismatched vectors.

Local soak found **zero** divergences and **zero** panics: **13.6M+** executions on `equivalence` and **10.3M+** on `robustness`. Both targets are built and smoke-run in CI (the new `fuzz` job).

> **Why `equivalence` bounds its inputs.** Components are clamped to `[-1e3, 1e3]` (non-finite → `0.0`). SIMD and scalar accumulate in different orders, so for unconstrained `f32` they legitimately differ — one path can overflow to `inf` where the other stays finite, purely from summation order. Bounding keeps every comparison in the regime where the two paths *must* agree, so a divergence is a real defect rather than a floating-point artifact. Non-finite **equivalence** stays covered by the differential test's adversarial corpus; non-finite **no-panic** by the `robustness` target.

### `compute_scalar` — a per-call scalar oracle (testing-only)

The equivalence fuzzer needs both the SIMD and scalar result for the *same* input in one process, which the process-sticky `force_scalar` cannot provide. `compute_scalar(metric, a, b)` computes a metric on the scalar path directly, bypassing dispatch and touching no global state. It is gated on `feature = "testing"` and is **not** part of the stable surface — same status as `force_scalar` and `which_kernel`.

## API freeze

The stable public surface declared frozen at the 0.4.0 feature freeze is now **locked for 1.x** (recorded in `dev/ROADMAP.md`): the five metric tags, the `Distance` trait, the `compute` / `compute_batch` dispatchers, `cosine_normalized` / `normalize`, the feature-detection surface (`CpuFeatures` / `detect_features` / `forced_scalar`), and `VERSION`. Only additive, non-breaking changes land before 2.0. The testing-gated accessors (`force_scalar`, `which_kernel`, `compute_scalar`) remain outside the guarantee.

## Breaking changes

**None.** Everything in 0.5.0 is additive (and the one new public item is testing-gated).

## Verification

Verified on **Windows x86_64** and **Linux x86_64 (WSL2 Ubuntu)**, each on stable (1.95.0) and the 1.87 MSRV, with the **aarch64** NEON path compile-and-lint-checked via `--target aarch64-unknown-linux-gnu`, and the fuzz targets built and soaked on nightly. The CI matrix runs across Linux, macOS, and Windows on stable and 1.87, plus dedicated `security` and `fuzz` jobs:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo test --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo deny check
cargo audit
cargo +nightly fuzz build && cargo +nightly fuzz run equivalence -- -max_total_time=60
```

All green. Test totals at this tag: **66** on default features and **76** with `--all-features` (unit + integration + doctests), across happy-path, property-based, edge-case, low-magnitude, normalized, and SIMD-differential suites — now backed by the two fuzz targets. `cargo deny check` reports `advisories ok, bans ok, licenses ok, sources ok`.
