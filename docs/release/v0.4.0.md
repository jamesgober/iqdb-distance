# iqdb-distance v0.4.0 — Normalized Fast Path + Feature Freeze

**The surface is complete.** v0.4.0 adds the pre-normalized cosine fast path for embeddings that are already unit length, then **freezes the public API** for the 1.x series. From here only additive, non-breaking changes land before 2.0 — the math surface the index crates build on is now a fixed point.

## What is iqdb-distance?

The innermost loop of the iQDB vector database. Given two `&[f32]` slices and a metric it returns the distance (or similarity) as an `f32`, picking the fastest available kernel (AVX2 / NEON / scalar) at runtime. Five metrics behind one `Distance` trait, a runtime dispatcher over the `DistanceMetric` tag, allocation-free batch evaluation, and — as of this release — a fast path for normalized embeddings.

## What's new in 0.4.0

### `cosine_normalized` — the fast path for unit vectors

When embeddings are L2-normalized up front (a common ingest step), cosine distance collapses to `1 − (a · b)`: the per-call norm, square root, and division the general `Cosine` kernel performs are all unnecessary. `cosine_normalized` evaluates only the dot product, through the same runtime-dispatched SIMD kernel — on the order of 2–3× less arithmetic on the most common metric.

```rust
use iqdb_distance::cosine_normalized;

// Identical unit vectors → 0; perpendicular → 1.
let a = [1.0_f32, 0.0, 0.0];
assert!(cosine_normalized(&a, &a).expect("valid pair").abs() < 1e-6);
assert!((cosine_normalized(&a, &[0.0, 1.0, 0.0]).expect("valid pair") - 1.0).abs() < 1e-6);
```

For genuinely unit-length inputs the result equals `Cosine::compute` within floating-point tolerance and stays in `[0, 2]` — an equivalence that is property-tested against the full cosine kernel over generated vectors. The contract is explicit: the caller guarantees unit length; when magnitudes are unknown, use `Cosine`, which normalizes internally.

### `normalize` — produce the unit vectors it expects

```rust
use iqdb_distance::normalize;

let unit = normalize(&[3.0_f32, 4.0]).expect("non-zero magnitude"); // → [0.6, 0.8]
assert!(normalize(&[0.0_f32, 0.0, 0.0]).is_err());                  // zero can't be normalized
```

`normalize` returns the `v / ‖v‖` copy of a vector (squared norm via the SIMD dot kernel), for normalizing once at ingest. It rejects empty, zero-magnitude, subnormal-magnitude, and non-finite-norm inputs with `IqdbError::InvalidVector` — a vector you cannot turn into a unit vector is rejected, not returned as `NaN`s. It is the crate's one allocating call, by necessity: it produces a new vector.

### Why two free functions

The roadmap's "normalized variants" could have been a parallel `CosineNormalized` metric type or a new `DistanceMetric` enum variant. Both were rejected to keep the surface minimal: a parallel type doubles the cosine API and still can't be reached through the runtime `DistanceMetric` dispatcher (that enum lives in frozen `iqdb-types`). Two small free functions deliver the fast path with no new types and no coupling to the type crate.

## Feature freeze

The public surface is complete and **frozen for 1.x** (recorded in `dev/ROADMAP.md`):

- Metric tags `Cosine` / `DotProduct` / `Euclidean` / `Manhattan` / `Hamming`, the `Distance` trait, the `compute` / `compute_batch` dispatchers, `cosine_normalized` / `normalize`, the feature-detection surface (`CpuFeatures` / `detect_features` / `forced_scalar`), and `VERSION`.
- `force_scalar` / `which_kernel` remain gated behind `feature = "testing"` and are explicitly **not** part of the stable surface.

Additive, non-breaking changes remain allowed within 1.x; anything else waits for 2.0. There is no `todo!`/`unimplemented!` anywhere in shipping code.

## Breaking changes

**None to existing APIs.** Everything in 0.4.0 is additive on top of the 0.3.0 surface.

## Verification

Verified on **Windows x86_64** and **Linux x86_64 (WSL2 Ubuntu)**, each on stable (1.95.0) and the 1.87 MSRV, with the **aarch64** NEON path compile-and-lint-checked via `--target aarch64-unknown-linux-gnu`. The CI matrix runs the same across Linux, macOS, and Windows on stable and 1.87:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo test --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo deny check
cargo audit
```

All green. Test totals at this tag: **66** on default features (51 unit/integration + 15 doctests) and **75** with `--all-features` (55 unit/integration + 20 doctests), adding a dedicated normalized suite (hand-picked correctness, error paths, and a property test pinning `cosine_normalized(normalize(a), normalize(b)) == Cosine(a, b)`). `cargo deny check` reports `advisories ok, bans ok, licenses ok, sources ok`.
