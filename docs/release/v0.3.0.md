# iqdb-distance v0.3.0 — SIMD

**The fast path arrives.** v0.3.0 joins the scalar reference with runtime-dispatched **AVX2** (x86_64) and **NEON** (aarch64) kernels for all five metrics. Every SIMD path is differentially tested to agree with its scalar twin — across finite *and* adversarial inputs — and the test that does it first proves the host actually dispatched to SIMD, so a silent fallback can never let the equivalence check pass vacuously.

## What is iqdb-distance?

The innermost loop of the iQDB vector database. Given two `&[f32]` slices and a metric it returns the distance (or similarity) as an `f32`, picking the fastest available kernel at runtime and falling back to a readable scalar reference when the host lacks the feature.

## What's new in 0.3.0

### AVX2 and NEON kernels for every metric

`src/simd/avx2.rs` and `src/simd/neon.rs` implement `dot`, `cosine`, `euclidean`, `manhattan`, and `hamming` with an eight-lane (AVX2) or four-lane (NEON) main loop and a scalar tail. Each kernel is an `unsafe fn` carrying `#[target_feature(enable = …)]` and is reachable only behind the runtime guard; every pointer-taking intrinsic carries a `// SAFETY:` note tying it to the `chunks_exact` source. The public API is unchanged — the same `Distance::compute` / `compute` calls now run on SIMD where available.

### Runtime feature detection and a single dispatch source of truth

```rust
let f = iqdb_distance::detect_features();
// On an AVX2 x86_64 host, `f.avx2` is true; on aarch64, `f.neon` is.
let _ = (f.avx2, f.neon, f.forced_scalar);
```

`detect_features()` probes the host once through a `OnceLock` and returns a `Copy` `CpuFeatures` snapshot. A single crate-private `select_kernel(CpuFeatures) -> Kernel` is the one place the dispatch decision is made — the per-metric routing and the testing-only `which_kernel` accessor both consult it, so they cannot drift.

### The `testing` feature: scalar override + kernel introspection

A new `testing` Cargo feature exposes `force_scalar()` (a sticky, process-wide override that pins dispatch onto the scalar path) and `which_kernel() -> &'static str` (the kernel dispatch would route to right now). A production build cannot reach either — SIMD can never be disabled at runtime by accident, and these testing accessors are explicitly **not** part of the stable surface.

### Differential SIMD-vs-scalar verification

The differential suite (`tests/differential.rs`, run under `--features testing`) closes two correctness gaps a naive equivalence test has:

- **"SIMD actually ran."** It asserts the host dispatched to its SIMD kernel *before* gathering SIMD samples. Without this, a runtime-detection regression that silently fell back to scalar would let a scalar-vs-scalar comparison report green.
- **Race-free collection.** `force_scalar()` is sticky for the process, so all SIMD samples are cached in a `OnceLock` *before* any test flips the flag — Cargo's parallel test execution can no longer interleave one test's flip with another's pre-flip gather.

Samples are compared across a finite sin/cos corpus and an adversarial corpus (NaN, ±∞, ±0.0, subnormals, ±1e30, ±1e-30, zero vectors, and low-magnitude colinear/orthogonal pairs) under an explicit non-finite contract: both NaN, or both ∞ with matching sign, or both finite within a tight epsilon.

### Criterion benches

`benches/distance.rs` (under `--features testing`) reports both the SIMD path and the forced-scalar path per metric at dim 768, so the SIMD headroom is measurable and tracked.

### `#[non_exhaustive]` metric handling

`iqdb-types` 1.0 made `DistanceMetric` `#[non_exhaustive]`. The runtime `compute` / `compute_batch` dispatchers now carry a wildcard arm returning `IqdbError::InvalidMetric` for any metric outside the implemented set — a future `iqdb-types` that adds a metric never breaks the dispatcher at runtime.

## Breaking changes

**None to the math API.** The `Distance` trait, the five metric types, and the `compute` / `compute_batch` signatures are unchanged from 0.2.0 — results are identical (the SIMD kernels match the scalar reference within tolerance), only faster. New surface (`detect_features`, `CpuFeatures`, `forced_scalar`, and the `testing`-gated accessors) is additive.

## Verification

Verified on **Windows x86_64** and **Linux x86_64 (WSL2 Ubuntu)**, each on stable (1.95.0) and the 1.87 MSRV, and the **aarch64** NEON path is compile-and-lint-checked via `--target aarch64-unknown-linux-gnu`. The CI matrix runs the same across Linux, macOS, and Windows on stable and 1.87:

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo test --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo deny check
cargo audit
```

All green on every combination, with the differential suite confirming AVX2 dispatched on both x86_64 hosts. Test totals at this tag: **51** on default features (36 unit/integration + 15 doctests) and **60** with `--all-features` (43 unit/integration + 17 doctests), spanning happy-path, property-based, edge-case, low-magnitude, and SIMD-differential suites. `cargo deny check` reports `advisories ok, bans ok, licenses ok, sources ok`. Zero `unsafe` outside the gated, runtime-guarded SIMD kernels, each with a `// SAFETY:` justification.

## What's next

- **v0.4.0 — batch refinements + normalized fast-paths + feature freeze.** Optimized batch kernels and a pre-normalized cosine path, then a declared feature freeze. (The exact normalized-API shape is held against the "keep the API simple" mandate.)
- **v0.5.0 — equivalence fuzzing + API freeze.** A `cargo-fuzz` SIMD-vs-scalar target and the locked public surface.
- **v0.6.0 → v0.9.x → v1.0.0.** RC soak against the real index consumers, then the stable release.
